# Headache-Yes-No-chart

頭痛チェックシート（[Headache-Yes-No](https://github.com/dr-mcy/Headache-Yes-No)）で患者がスマートフォンに記入した内容をQRコードで院内端末に取り込み、HIT-6 / MIBS-4 / MHD（頭痛日数）/ MMD（服薬日数）の推移をグラフ化するビューアです。

## 運用フロー

1. 患者が自分のスマートフォンで [Headache-Yes-No](https://headache-yes-no.vercel.app/) を開き、HIT-6・MIBS-4・過去4週間の日数を記入する。
2. 「QRコード」ボタンを押し、表示されたQRコードを院内端末（このアプリ）にかざす。
3. 院内端末側のこのアプリ（[Headache-Yes-No-chart](https://headache-yes-no-chart.vercel.app/)）でQRコードを読み取ると、患者ごとに記録が蓄積され、推移グラフ・一覧が更新される。

対応する取り込み方法:
- ライブカメラでの連続スキャン（登録後もカメラを止めずに次の患者を続けて読み取れる）
- QRコード画像ファイルの選択（カメラロール／その場で撮影）
- QRテキストの手動貼り付け

## バージョン運用（①②は同じバージョンで揃える）

- 頭痛チェックシート（①）とこのビューア（②）は**同じバージョン番号で揃えます**。片方だけ変更する場合も（改変していない側も）両方のバージョンを上げ、**同時に公開**してください。
- ①はQRテキストの2行目に `バージョン: vX.Y.Z` を出力します。②は新規にQRを登録するとき、この版が自身の版（`index.html` の `APP_VERSION`）と完全一致しない場合は**登録せず**、画面にエラーを表示します（版行がない旧版のQRも同様）。ライブカメラの連続読み取りでは、拒否後もカメラは止まりません。
- 既に保存済みのレコード、バックアップの復元、旧データの IndexedDB 移行には版チェックを適用しません（過去データはそのまま表示できます）。
- 版の定義は各アプリ1か所（`APP_VERSION`）です。②は `package.json` / `package-lock.json` の version も同じ値にします。

## データの保存について

- すべてのデータは**院内端末のブラウザ内（IndexedDB）にのみ**保存され、外部のサーバーには送信されません。
- 旧バージョンで `localStorage`（key: `headache_qr_data`）に保存されていたデータは、起動時に自動的に IndexedDB へ移行されます（移行を確認できた場合のみ旧データを削除します）。
- 端末のブラウザデータを消去する（プライベートブラウジング終了、ストレージ削除など）と失われます。定期的に「バックアップ」機能でJSONを書き出してください。

## 患者の識別（患者キー）

QRコード内の情報から、以下の優先順位で患者を識別します。

1. 病院ID（入力されていれば最優先）
2. 氏名 + 生年月日（病院IDが未入力の場合）
3. 氏名のみ（生年月日も未入力の場合）

同一患者・同一記入日のデータは重複として扱われ、内容が異なる場合は上書き確認、内容が完全に同一の場合は「登録済み」として何もしません。

## バックアップ

- 「バックアップ」→「JSONを書き出す」で全データをJSONファイルとしてダウンロードできます。
- 「バックアップ」→ファイル選択でJSONを読み込むと、既存データとマージされます。患者キー+記入日が既存データと衝突する場合は件数を表示し、上書きするかスキップするか選べます。
- CSV出力（生年月日・性別・病院ID・HIT-6回答・MIBS-4回答を含む）もダウンロードできます。

## 記録の編集

データ一覧の「詳細」→「編集」で、氏名・生年月日・性別・病院ID・担当医・記入日・4つの日数・HIT-6/MIBS-4の各回答・備考を手で直せます（「保存」「キャンセル」）。HIT-6/MIBS-4は全問回答すると点数と判定を再計算し、未完なら点数なしになります。同じ患者・同じ記入日の別の記録と重なる内容は保存できません。
編集した記録は詳細に「編集済み（日時）」、一覧の記入日の横に「編集」と表示され、QRの元のテキスト（生テキスト）は証跡としてそのまま残ります。編集済みの記録は、空にした項目が元のQRテキストから復元されません（バックアップの取り込み時も同様）。
編集した記録は**未書き出しに戻り、FileMaker連携で再書き出しされます**（同じ取込キーの行が再度追記されます。重複排除はせず、FileMaker側の更新マッチ処理で吸収する想定です。患者や記入日を変えると取込キーも変わるため、FileMaker側では別の記録として追加され元の記録は残ります。デモ記録は従来どおり除外）。

## デモ

画面最下部（版表示の上）の「デモ」ボタンで、架空の患者（病院ID `DEMO`・毎月1回（日付はばらつく）来院の10回分。全体は改善傾向ですが、途中に一時悪化もあり、最後の回で悪化する経過）を入れて、グラフや一覧の見え方を確認できます。デモデータは患者名の横に「デモ」と表示され、**FileMaker連携（自動書き出し・再書き出し・FileMaker用CSV・未書き出し件数）からは常に除外**されます（通常のCSV出力・印刷・バックアップには含まれます）。
「デモ」を再度押すとデモ分だけ入れ直し、「デモ削除」でデモ分だけを削除します（実データは変更されません）。

## FileMaker連携

QRコードから取り込んだデータを、別途稼働しているFileMaker側のセッションが定期的に取り込めるよう、契約されたCSV形式（v1）で書き出せます。**列・書式は変更しないこと**（変更する場合は契約バージョンを上げる）。

### CSV契約 v1

- 文字コード: UTF-8、BOMなし
- 1行目はヘッダー行
- 全フィールドを二重引用符で囲み、値中の `"` は `""` に二重化
- 改行はCRLF
- 列順:

  | # | 列名 | 内容 |
  |---|------|------|
  | 1 | 取込キー | 患者キー + `\|` + 記入日 |
  | 2 | 記入日 | `YYYY/MM/DD` |
  | 3 | 病院ID | |
  | 4 | 氏名 | |
  | 5 | 生年月日 | `YYYY/MM/DD`。y/m/dのいずれかが未入力なら空欄 |
  | 6 | 性別 | |
  | 7 | 担当医 | |
  | 8 | 頭痛日数 | |
  | 9 | 服薬日数 | |
  | 10 | スッキリせず日数 | |
  | 11 | スッキリ日数 | |
  | 12 | HIT6合計 | |
  | 13 | HIT6判定 | |
  | 14-19 | HIT6_Q1〜Q6 | 各設問の回答(1-5)。未回答は空欄 |
  | 20 | MIBS4合計 | |
  | 21 | MIBS4判定 | |
  | 22-25 | MIBS4_Q1〜Q4 | 各設問の回答(1-6)。未回答は空欄 |
  | 26 | 備考 | 改行はリテラル `\n`(バックスラッシュ+n の2文字)に置換 |
  | 27 | 登録日時 | ISO8601 |
  | 28 | 契約版 | `1` |

CSV生成は `parser.js` の純関数（`buildFileMakerCsv` / `appendFileMakerCsv` / `buildFileMakerRow`）で行い、`test/filemaker.test.js` で引用符・改行・空欄・XSS文字列を検証しています。

### 書き出し方法

- **Chrome / Edge（File System Access API対応）**: 「FileMaker連携」カードの「書き出しフォルダを選択」で共有フォルダを1回選ぶと、以後はQR登録のたびに自動で `headache_inbox.csv` にその時点の未書き出し分を追記します。ファイルが既に存在する場合は既存内容を読み込んでから新しい行だけを追記します（重複排除はしません。FileMaker側の更新マッチ処理で吸収する想定です）。
  - アクセス許可が切れた場合（`queryPermission` が `granted` でない場合）は画面上に明示し、「アクセスを許可」ボタンから再許可できます。書き込みに失敗した場合も画面上に明示されます（サイレント失敗はしません）。
  - 未書き出し件数は常に画面上に表示され、「未書き出し分を再書き出し」ボタンでいつでも再試行できます。
- **File System Access API非対応（iPad/Safari等）**: 「FileMaker用CSVを保存」ボタンで未書き出し分を `headache_inbox.csv` としてダウンロードします。ダウンロード後、書き出し済みとしてマークするかどうかを確認ダイアログで選べます。

### フォルダ運用（FileMaker側との受け渡し）

1. このアプリが共有フォルダに `headache_inbox.csv` を書き出す（追記）。
2. FileMaker側は定期的にこのフォルダを監視し、`headache_inbox.csv` を見つけたら `processing_<timestamp>.csv` のような名前にrenameしてから読み込む（このアプリが書き込み中のファイルを読まないようにするため）。
3. 取り込みに成功したら `archive/` フォルダへ、失敗したら `error/` フォルダへ移動する。

### 検証状況

- CSV生成の純関数（引用符・改行・空欄・XSS文字列・追記）は `node --test` で自動検証済みです。
- 「FileMaker用CSVを保存」（File System Access API非対応環境向けの手動ダウンロード経路）は `test/filemaker-browser.integration.js` で自動検証済みです。
- `showDirectoryPicker()` によるフォルダ選択・自動書き出し・権限の再取得（File System Access API本体の経路）は、ネイティブのフォルダ選択ダイアログを伴うため自動テストできません。**未検証**です。Chrome/Edgeで実際にフォルダを選択し、QRコードを読み取って `headache_inbox.csv` が作成・追記されること、権限を取り消した状態で警告が表示されることを手動で確認してください。

## 印刷

患者を1名選択した状態で「印刷」を押すと、患者情報・サマリー・全グラフ・記録一覧をA4縦のレポートとして印刷できます（操作ボタン等は印刷時に非表示になります）。

## デプロイ（Vercel）

本リポジトリの `main` ブランチは Vercel で自動デプロイされ、以下のURLで公開されています。

- ② グラフビューア（本リポジトリ）: https://headache-yes-no-chart.vercel.app/
- ① 患者記入シート（Headache-Yes-No）: https://headache-yes-no.vercel.app/

静的ファイル配信のため `vercel.json` 等の追加設定は不要です。`parser.js` は `index.html` から相対パス (`<script src="parser.js">`) で読み込んでおり、Vercel の静的ホスティングでもそのまま動作します。

## テスト方法

### 単体テスト（parser.js の純関数）

```sh
node --test
```

QRテキストのparse・患者キーの優先順位・日付処理・XSSエスケープなどを検証します。

### 結合テスト（① の実際の QRコード生成 → ② への取り込み）

```sh
npm install
npx playwright@1.52.0 install chromium   # 初回のみ
node test/e2e.integration.js
```

- ①（`/Users/admin/Projects/Headache-Yes-No/index.html` のローカルclone）を開いて synthetic な患者データを入力し、実際の `buildQrText()` の出力を取得します。
- そのテキストを②へ手動入力で登録し、記入日・日数・患者キーなどが期待値と一致するか検証します。
- ①の `qrcode-generator` で生成したQR画像を②の画像選択（ファイル入力）で読み込めることも確認します。
- モバイル(375px)・デスクトップ幅のスクリーンショットを `.tmp-test/` に保存し、横スクロールが発生していないか確認します。

実患者データは一切使用しません。

### 性能計測（3,000件 synthetic データ）

```sh
node test/perf.test.js
```

1日あたり約100名 × 数か月分を想定した synthetic 3,000件（患者800名）をIndexedDBに投入し、起動時の初期表示・患者検索・グラフ描画にかかる時間を計測します。

### FileMaker連携（手動ダウンロード経路）の自動テスト

```sh
node test/filemaker-browser.integration.js
```

「FileMaker用CSVを保存」（手動ダウンロード）→書き出し済みマークの一連の流れを検証します。`showDirectoryPicker()`によるフォルダ自動書き出しはネイティブダイアログのため自動テストできません（上記「FileMaker連携」節を参照）。
